Arabic-first (RTL) bilingual website for the Iraqi–British Business Council (IBBC), built on Next.js 16 App Router, Tailwind v4 and next-intl v4. The design spec is `docs/superpowers/specs/2026-11-02-ibbc-website-design.md`. The sibling `aldallah-group-landingpage` is the source of the toolchain and conventions.

## Content rules

- **No placeholders, ever.** Nothing in brackets, no dummy names, no sample logos.
- **A section with no confirmed data renders nothing**, and its menu entry and anchor go with it. Supplied today: the Vice Chairman, Sohaib Mohammed Abdullah, and the phone +964 790 199 9998, both from the business card in the identity deck and pending the council's confirmation. Everything else (advisors, team, partners, address, email, hours, social) stays omitted until supplied.
- **No invented facts.** No person, member company, partner, address, phone number, figure, date or event that the project lead has not supplied.
- **No JBBC copy.** No JBBC sentence, maroon colour, wave banner pattern or Brown typeface. London imagery is allowed sparingly (the About two-cities frame), since the project lead asked for imagery like the original website (2026-11-02); a full-width London-landmark band stays out.
- **Draft copy goes live and is reviewed later.** Descriptive wording written for this build is listed in the README under "Draft copy for review". Confirmed facts are a separate kind and only the council can give them.
- Name: `IBBC`, `Iraqi–British Business Council` (Iraq first, en dash), `مجلس الأعمال العراقي البريطاني`.
- Image alt text describes the photograph and never presents stock as the council's own.

## Design tokens

Colours are defined only in `src/app/tailwind.css`: blue `#0B2470`, blue-deep `#071A55`, red `#CE1126` (the Iraqi flag red, at the project lead's request), ivory `#F3EEE4`, white `#FFFFFF`, ink `#14204A`, muted `#545B78`, line `#E4DCCB`. Red is an accent only, never a large background and never text below 18px. Text is never coloured with opacity.

Layout and type follow the team's Baghdad Expo site, at the project lead's request (2026-11-02). The `shell` utility is the one container: up to `--shell-max` (112.5rem, 1800px) wide, with `--shell-pad` side padding of 24px, 40px from 640px, 80px from 1024px and 112px from 1280px. Both are custom properties on `html`, so anything that must line up with the container (the hero text cap) derives from them instead of copying numbers. `<main>` is the only source of space between top-level blocks: `gap-24 lg:gap-32` and the same bottom padding (96 and 128px); no top-level block adds outer `py` or `mt`. Inside a block, a `SectionHeading` sits `gap-10 lg:gap-12` above its content, card grids use `gap-6 lg:gap-8`, the blue bands pad `py-16 lg:py-20` and `PageHeading` `py-16 lg:py-24`. Prose is capped in `ch` per block, never by the container. The scale is `text-hero` 48 to 76px (Home title only; kept compact so the English title stays within four lines and the buttons within a 1024×768 screen), `text-display` 44 to 72px (inner-page titles), `text-headline` 36 to 60px (section titles), and the hero is larger than the display, and the display than the headline, at every width. Tier names on Membership are card titles (`text-title`), below the section title.

Fonts through `next/font/google`: Cormorant SC 600 (English headings), Amiri 400/700 (Arabic headings), Inter (English body), IBM Plex Sans Arabic 400/500/600 (Arabic body). Arabic never gets small caps or letter-spacing. The hero title is the largest text at every width; form inputs are 16px; tier feature text is at least 15px.

## Motion

Added on 2026-11-02 at the project lead's request ("a bit of animation or smoothness"). The aim is an institution that feels considered, not a product that performs: motion supports the content, never delays reading it, never decides whether it is visible, and never loops. GSAP (with ScrollTrigger and `@gsap/react`) and Lenis, the same versions as Al-Dallah; `src/lib/gsap.ts` registers the plugins once.

The vocabulary, and nothing beyond it:

1. **Hero entrance on load, in CSS** (`enter-*` utilities in `tailwind.css`), so it runs before hydration and needs no JavaScript: the two flag photographs settle from 1.08 to 1 over 1.8s, the red seam draws from the top, then the other-language line, title, red rule, sentence and buttons rise and fade in 90ms apart (`[--enter-step:n]`). The red rule grows from the reading-start edge: `rule-red` sets `transform-origin` to the left, and to the right under `:dir(rtl)`.
2. **Page headings on load, in CSS**: the same, shorter (`[--enter-base:120ms] [--enter-duration:800ms]`), the photograph settling from 1.04, the pills fading in last.
3. **Section reveals** with the `Reveal` client component (`variant`: `rise`, `frame`, `sequence`, `stagger`). `SectionHeading` reveals itself as a sequence (title, then the red rule drawing from the reading-start edge via `data-reveal="rule"`, then the lede). `IconCardGrid` and every other card list stagger their cards 0.08s apart. `SplitPhotoFrame` and the Why join photographs fade in while the photograph (`data-reveal-zoom`) settles from 1.04; the split frame's seam (`data-reveal-draw`) draws from the top like the hero's. Durations 0.9 to 1.1s, `power3.out` and `expo.out`; opacity and transforms only.
4. **Parallax** with the `Parallax` client component on the hero flags, each `PageHeading` photograph and the two `PhotoBand`s: a ScrollTrigger scrub moves the photograph layer through yPercent 0 to 5 (from the top of the page) or -5 to 5 (mid-page bands), scaled 1.12 so no edge shows. Only under `(prefers-reduced-motion: no-preference) and (pointer: fine)`, where Lenis drives the scroll and the layer moves in the same frame; native touch scrolling would make it judder. The veils and the text never move. **The 1.12 scale is CSS, not GSAP** (the `parallax-layer` utility, under the same media query), so the server-rendered photograph is already at its final size on the first paint; when GSAP set the scale at hydration, the hero and page-heading photographs visibly jumped 12% mid-entrance. GSAP merges the CSS `scale` into its own transform and animates only `yPercent`. No `backdrop-filter` over a scrubbed layer: the Vision and mission cards lost their blur for that reason (their text still measures 7.22:1).
5. **Hover and press, in CSS, only under `(hover: hover)` and `motion-safe`**: cards lift 3px with a soft ink shadow (`card-lift`), photographs in cards zoom to 1.05 over 700ms, buttons lift 1px and press to 0.97, the nav underline stays.
6. **Smooth scrolling** with Lenis (`SmoothScroll` in `src/lib/smooth-scroll.tsx`, mounted once in `SiteShell`), synced to the GSAP ticker and ScrollTrigger. Same-page `#` links (the skip link, the About and Membership pills) scroll through Lenis, which honours `scroll-padding-top`, push the hash and move focus to the target (a section gets a temporary `tabindex="-1"` and no outline). A malformed hash is ignored. ScrollTrigger refreshes on load, when fonts are ready, and on every pathname change once the new page's images have decoded (capped at 1.5s). Cross-page links such as `/membership#tiers` stay with Next, which lands them under the header.

No continuous or looping animation, no cursor effects, no counters, no page transitions.

**Rules that keep content visible:**

- **`Reveal` triggers on `IntersectionObserver`, never ScrollTrigger.** ScrollTrigger caches start positions; when images or fonts shift the layout afterwards, a jumped-past trigger never fires and content stays at opacity 0 (this happened in Al-Dallah). The observer's root margin reaches 100,000px above the viewport, so a target that a jump (End, an anchor, scroll restoration) carries past is still reported and set to its finished state at once.
- **Only content below the fold at hydration is hidden.** Whatever is on screen when `Reveal` mounts stays as rendered, so nothing flashes off and on; the hero and page headings have their CSS entrance instead.
- **Every reveal ends by clearing its inline `opacity` and `transform`**, so hover transforms and printing work. A print rule forces the elements Reveal animates (the root, its direct children and the `data-reveal-zoom` and `data-reveal-draw` targets) visible anyway.
- **Reduced motion renders the finished state outright.** The CSS entrances sit inside `prefers-reduced-motion: no-preference`; `Reveal` does nothing (`useGSAP` with `revertOnUpdate: true` reverts if the preference flips); `Parallax` uses `gsap.matchMedia`; Lenis is not created. With JavaScript off, nothing is hidden: the server renders no inline opacity and the CSS entrances end at the normal state (`animation-fill-mode: backwards`, so they never hold a value after finishing).
- **The mobile menu stops Lenis while it is open** (`useLenis()` from the `LenisContext`; `lenis.stop()` on open, `lenis.start()` on close) so the body scroll lock holds, and the sheet carries `data-lenis-prevent` so it scrolls natively. The menu sheet drops in (360ms) and its backdrop fades (240ms), both `motion-safe`.
- **The header switch on Home still reads `window.scrollY` on `scroll`**: Lenis scrolls the window, so native scroll events keep firing.
- **The parallax changes the pixels behind photo text**, so the hero and banner contrast was re-measured with it active (2026-11-02), see the two contrast traps below. Re-measure whenever a parallax range or scale changes.

## Traps carried over from Al-Dallah

- **The proxy matcher needs a double backslash** (`.*\\..*` in the string literal in `src/proxy.ts`, which the regex receives as `.*\..*`). With a single one the lookahead rejects every non-empty path: unprefixed URLs like `/about` 404 instead of redirecting. Lint, types and build stay green. `scripts/smoke.mjs` checks `/about` redirects to `/ar/about`.
- **`setRequestLocale` in every layout and every page**, or the subtree silently leaves static generation. Check for `●` in the build's route table.
- **Never render a content string raw on an Arabic page.** Latin and numeric runs ("IBBC", "PDF", "4 MB", years) go through `RichText` and `LtrRun` so they read in the right order. Check by walking the text nodes of `html[lang=ar] main` for `[A-Za-z0-9]` without a `dir="ltr"` ancestor. An `<option>` cannot hold an element, so select labels go through `isolateLtrRuns` (U+2068 and U+2069 around each run) instead; the walk lists them, and each run must sit between those two marks.
- **The enquiry forms submit through `startTransition`, not the bare `action`.** React 19 resets an uncontrolled form after every server action, including one that returns validation errors, so a mistyped field lost every value and the attachment. Build `FormData` in `onSubmit`, call `formAction` inside `startTransition`, reset by hand only on success, and keep `action={formAction}` for the no-JavaScript path.
- **Server actions do not receive `[locale]`.** Read a hidden `locale` field and validate it against `routing.locales`.
- **Contrast is solved against the darkest surface** a text colour sits on, not the lightest.
- **Text over a photograph cannot be audited from CSS.** Measure the text boxes against real viewport-screenshot pixels, at 360, 768, 1440 and 1920 wide in both languages.
- **Hero layout and contrast (2026-11-02).** Below 640px the hero is a 16rem flag band (Iraq on the reading-start side, the red seam starting below the header so it never crosses the header name) above the text on solid `blue-deep`; from 640px the flags fill the hero with the text over them. Both flags must stay recognisable: the veil (`hero-veil`, mirrored by swapping two custom properties with `rtl:hero-veil-mirrored`, in `tailwind.css`) is deep only at the header strip and behind the lower text, and light over the upper flags. It is solved against the brightest pixel behind each text box, one gradient set per breakpoint. All hero text is white: `on-blue-muted` falls to 3.7:1 where a line crosses the red seam (at 640 to 1279px the text block spans both halves); white is 5.63:1 on the seam (computed after the switch to the Iraqi flag red `#CE1126` on 2026-11-02; the other values were measured on the old red and white-on-red still passes 4.5:1). From 1280px (`xl`) the text block ends 2rem before the seam; its cap is `50vw` minus the shell's start edge (`max(var(--shell-pad), (100vw - var(--shell-max)) / 2 + var(--shell-pad))`) minus 2rem. Lowest values after the compact hero title (2026-11-02), at 360, 768, 1024, 1280, 1440 and 1920 in both languages: title 3.62:1 (`/en` at 1024, hero-size text, bar 3:1), other-language line 4.86:1 (`/ar` at 1024), sentence 5.57:1 (`/ar` at 768), header name 8.08:1 (`/ar` at 768), header links 5.63:1 (`/ar` at 1024, over the seam), 8.22:1 elsewhere; the white button label (13.99:1) and the red button label, language switch and Contact pill (5.63:1) are computed on their own fills. At 360 the text sits on solid `blue-deep` (16.3:1). Re-measure whenever the photographs, the veil or the hero text move. **With the parallax active (2026-11-02)**, measured at rest (scale 1.12, yPercent 0) at 360, 768, 1024, 1280, 1440 and 1920 in both languages, and scrolled 200px at 1024 and 1440: title lowest 3.65:1 (`/en` at 1024, scrolled; 3.94:1 at rest on `/ar` at 1024), other-language line 4.77:1 (`/ar` at 1024), sentence 5.63:1, header links 5.63:1 (over the seam), header name 9.7:1 or more and its two small name lines 5.36:1 or more (`/en` at 768).
- **Photo banners and contrast (2026-11-02).** Every inner `PageHeading` sits over a stock photograph under `photo-veil-start` (even 82 to 88% `blue-deep` below 1024px; from 1024px 92% on the reading-start side falling to 40% at the far edge, mirrored with `rtl:photo-veil-mirrored`), and the two Home `PhotoBand`s under `photo-veil` (84%, 72% in the middle, 84%). Measured against viewport-screenshot pixels at 360, 768, 1440 and 1920 in both languages, header hidden, text made transparent, the red rule hidden, brightest pixel per text box: lowest title / other text per banner, Vision and mission 8.24 / 7.24 (card titles count as other text), membership band title 7.1 (its red button is on its own fill), About 11.46 / 6.64 (pills included), Membership 10.17 / 5.72, Application 9.61 / 6.54, Contact 10.01 / 4.91 (`/en` at 1440, the lede reaching into the lighter veil over the bridge), Privacy 10.5 / 6.22, Terms 10.5 / 5.59. The Contact lede is the tightest: a longer lede there, a brighter photograph or a lighter veil needs a re-measure. **With the parallax active (2026-11-02)**, every banner passes: page headings at rest at 360, 768, 1440 and 1920 lowest title 9.71:1 and other text 4.82:1 (Contact lede, `/en` at 1440; the About pills, measured after scrolling their row into view, 11.1:1 or more); the two Home bands at the top, centre and bottom of the viewport lowest title 7.07:1 and card text 7.27:1. Scrolled 100, 200 and 300px at 1440 and 1920 in both languages (text under the header excluded), lowest title / other text per page heading: About 12.03 / 6.52, Membership 10.96 / 5.7, Application 11.45 / 7.58, Contact 11.26 / 4.88 (`/en` at 1440, 200px), Privacy 11.82 / 6.24, Terms 11.82 / 5.6. Re-measure whenever a banner photograph, its position, the veil, the parallax or the text over it changes. Photographs behind text are decorative (`alt=""`); only `PageHeading` images load eagerly.
- **No `loading.tsx` in any route.** It makes the prerendered body stream into a hidden `<div>` outside `<main>`, so the content stays invisible until JavaScript runs; `scripts/smoke.mjs` checks the Home `h1` and standing line are inside `<main>` in the static HTML.
- **A backgrounded tab reports a broken page.** React's streaming reveal waits for `requestAnimationFrame`. Foreground the tab before measuring.
- **Measuring too early reports a broken page.** Wait for `readyState === "complete"`, decode images with a capped wait, and force `Reveal` content to opacity 1 before measuring. After a scroll, wait about 1.5s for reveals and the Lenis glide to finish; a Playwright `hover()` right after `scrollIntoViewIfNeeded` can report no hover while the page is still gliding.
- **Titles must let their text shrink.** Long words overflow 360px screens without any box sticking out: use `hyphens-auto [overflow-wrap:anywhere]` and check `scrollWidth > clientWidth`.
- **Arabic is a connected script and never takes letter-spacing.**
- **A visually hidden control shows its focus on the visible wrapper, as the site's blue outline.** The tier cards and the attachment drop zone on `/membership/apply` wrap `sr-only` inputs. A 25% blue ring there was barely visible on white, and on a checked tier card it replaced the solid selection ring, so focus made the card look less selected. They use `has-[:focus-visible]:outline-2 outline-offset-3 outline-blue`, matching the base `:focus-visible` rule.
- **Measure 360px overflow with the scrollbar hidden.** A desktop browser window 360 wide lays the page out at 345px beside its scrollbar, so `scrollWidth === 360` never holds. Add `html { scrollbar-width: none }` before measuring. The About pills scroll sideways inside their own `overflow-x-auto` row by design.
- **The contrast audit cannot see the transparent header over the Home hero.** Hide the header before running `scripts/audit-contrast.js` on Home and measure it against hero pixels instead.

## Conventions

No code comments. No `any`, no `@ts-ignore`, no `React.FC`. Server Components by default, `"use client"` on leaves only. Logical properties only (`ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`), never `left`/`right` utilities. Files and folders are `kebab-case`, components `PascalCase`. Prop types live in `types/<component>-props.ts` inside page folders and flat beside shared components. Repositories keep `<name>_repo.ts` and `<name>_impl.ts`.

Commit messages carry no `Co-Authored-By` trailer. Work happens on `feat/first-release`; `main` is reached only through a pull request.

## Verification

`npm run gitcheck` (lint, format, test, clean build), then `npx next start -p 3100` and `npm run smoke`. Unit tests are `vitest` under `tests/`.

For motion, on every page in both languages at 1440 and 360: wheel-scroll to the bottom, return to the top and assert that no element in `<main>` has a computed opacity below 1 and no `[data-reveal-root]` element keeps an inline transform; repeat with an instant jump to the bottom and back; then emulate `prefers-reduced-motion: reduce` and assert the same immediately after load with `document.getAnimations()` empty and no `lenis` class on `html`; load each page with JavaScript disabled and assert nothing is below opacity 1. Check the pills and the skip link land 128px from the top with focus on the target, and the mobile menu stops page scrolling (`lenis-stopped`) while open.

In the browser, against the running build, on all seven pages in both languages: `scripts/audit-contrast.js` (a browser script copied from Al-Dallah: inject it with Playwright's `addScriptTag({ path })` and call `auditContrast(document)`, which returns `{ total, failures, belowAAA }`) at 360, 768 and 1440 wide, expecting no failures; the hero pixel measurement above; the Arabic direction walk; the 360px overflow check; and a keyboard pass (the skip link first and landing on `#content`, visible focus on every control, the mobile menu trapping focus, closing on Escape and returning focus to its button). The first release passed all of these on 2026-11-02.
